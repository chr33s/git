# @chr33s/git

> **Universal AI-native Git smart-HTTP protocol server, browser client & Unix CLI**  
> Built on Effect v4 with modern TypeScript and Web APIs.

One implementation of Git's core runs everywhere: inside a **Cloudflare Durable Object**, on **plain Node.js**, in a **browser tab**, or directly as a **Unix CLI**. Standard Git clients clone from it, push to it, and read the index and history generated by its commands.

Git+ extends normal source history with Git-native collaboration, agent sessions, repository context provenance, runtime audit telemetry, and durable repository knowledge. The repository remains the durable system of record rather than requiring a hosting-provider API or observability backend to reconstruct what happened.

---

## Why Git-Native & Agent-First?

- **The whole project fetches:** Source code, developer identities, key logs, pull requests, code reviews, automated checks, agent sessions, and audit records live inside native Git objects and refs. A normal fetch can replicate the durable collaboration and provenance graph.
- **The forge runs in the sandbox:** One core engine serves requests across Durable Objects, local Node processes, browser tabs, and terminal environments. Ephemeral agent containers can host, review, and merge code locally without third-party API rate limits.
- **Capability-scoped authority:** Permissions are bound to explicit capabilities (`source:push`, `hub:check:test`). Short-lived tokens are minted via member SSH keys without relying on centralized token registries.
- **Cryptographic authorship:** Reviews, decisions, attestations, trace records, and trust changes are SSH-signed and tied to exact repository state. Self-approvals are rejected at the protocol level.
- **Auditable agent context:** Context Packs identify the exact Git tree, blobs, byte ranges, and submodule gitlinks supplied as repository evidence. ContextRender commits to the final ordered semantic placements and bytes that cross the harness invocation boundary.
- **Native runtime telemetry:** Harness-native OpenTelemetry GenAI spans/events/logs are normalized into a signed, policy-invisible audit trace. OTel trace/span IDs remain correlation identifiers; Git record OIDs remain the durable audit identity.
- **Durable repository knowledge:** Human- and agent-readable Knowledge Concepts live in ordinary source history, cite signed provenance, carry structured Git evidence dependencies, and feed a bounded Repository Memory projection. OKF-compatible import/export keeps the corpus portable without making external metadata authoritative.
- **Built for concurrent agent workflows:** PR collaboration, sessions, tasks, and trace histories preserve causal DAG structure rather than inferring causality from timestamps.
- **Containable errors:** Retroactively revoke compromised keys to invalidate past events, or issue replicating tombstone events to scrub leaked secrets without breaking hash chains.

## Quick Start

### Installation & System Requirements

Requires **Node.js ^22.18.0** or a compatible Web API runtime.

```bash
# Run directly via npx
npx @chr33s/git --help

# Or install globally
npm install -g @chr33s/git
```

### Running a Server

Both server implementations speak standard **Smart-HTTP (v0/v2)**, **Git LFS**, and export a type-safe **JSON API**.

```bash
# Serve local repositories on port 8080
GIT_ROOT=./repos git+ serve --port=8080

# Serve with write access enabled for un-guarded repositories
GIT_ROOT=./repos git+ serve --port=8080 --open
```

Standard Git clients can interact directly with the server:

```bash
git clone http://127.0.0.1:8080/my-repo.git
```

## Agent-Native Collaboration & Provenance

The hub extension ([`docs/hub.md`](docs/hub.md)) brings PRs, tasks, identity, sessions, and signed agent audit history directly into Git refs.

```text
refs/
├── meta/
│   ├── trust/
│   │   └── genesis             # Member SSH authority & capability log
│   └── pull-requests/
│       └── pr-42               # Append-only review DAG
├── hub/
│   ├── task/                   # Agent task assignments & resolutions
│   ├── session/                # Distilled policy-visible session provenance
│   └── trace/                  # Detailed policy-invisible agent audit trace
└── notes/
    └── hub/memory              # Bounded Repository Memory projection
```

Durable Knowledge Concepts are ordinary versioned repository files, conventionally under:

```text
.gitplus/knowledge/
  index.md
  architecture/
  conventions/
  gotchas/
  playbooks/
  decisions/
```

### Task Coordination & Sessions

- **Task Coordination (`git+ task`):** Fleets organize directly inside the repository. Tasks record requirements, claims, hierarchy, and resolutions as signed events under `refs/hub/task/`. Claims are leases and naturally expire when an agent disappears.
- **Session Tracking (`git+ session`):** Records what an agent was instructed, decisions requested/resolved, what the session produced, and compact aggregate usage.
- **Repository Memory (`git+ session memory`):** Rebuilds or reads a bounded projection of reusable repository knowledge. Memory is cited data, not instruction authority.
- **Automated Wake Triggers (`git+ wake`):** Runs repository-defined execution rules when relevant refs change.

```bash
# Claim work
git+ task claim --id="task-102" --ttl="15m"

# Inspect the session that produced a branch
git+ session show --branch=feature/auth my-repo

# Rebuild and display Repository Memory
git+ session memory --distill my-repo
```

### Context Packs & Context Exposure

[`docs/context-pack.md`](docs/context-pack.md) defines the exact repository evidence supplied to an auditable invocation.

A Context Pack is grounded in one effective Git tree and contains typed evidence:

```text
blob
  path + blob OID + optional byte range

gitlink
  path + mode 160000 + submodule commit OID
```

The corresponding Context Exposure record retains the effective `view.tree` through a real Git tree edge and commits to the final ContextRender. The ContextRender digest binds segment order, semantic placement, media type, and exact body bytes, so moving identical bytes between developer/user/tool placements changes the commitment.

```bash
# Build repository context for a task
git+ context for --task="fix authentication policy"

# Explain why an item is in a persisted pack
git+ context why sha256:8d7ad4... src/auth.ts

# Verify a historical exposure and its Git evidence
git+ context audit sha1:abc123...
```

### OpenTelemetry GenAI & the Flight Recorder

[`docs/telemetry.md`](docs/telemetry.md) defines runtime audit telemetry. Harness-native OpenTelemetry GenAI is the default runtime semantic input:

```text
harness OTel GenAI signals
        ↓
loss-intolerant Git+ audit ingest
        ↓
versioned semconv normalization
        ↓
signed refs/hub/trace/<session>
```

The normal observability export can independently sample, aggregate, transform, and expire. The Git+ audit branch preserves selected durable facts and reports partial/unknown coverage when loss or transformation is known.

One compliant GenAI inference span maps to one logical invocation. Requested and response models stay distinct, finish reasons remain separate from errors, and provider retries remain subordinate attempts unless the upstream instrumentation exposes another logical span.

```bash
# Inspect the signed trace joined to a session
git+ trace show 0198f2aa...

# Fallback ingestion for a harness without suitable native OTel
git+ trace record my-repo \
  --session 0198f2aa... \
  --key ~/.ssh/id_ed25519 \
  --event event.json
```

### Durable Knowledge Concepts

[`docs/knowledge-durability.md`](docs/knowledge-durability.md) separates durable publication from bounded recall:

```text
signed sessions / decisions / evidence
        ↓
Durable Knowledge Concepts
        ├──→ Repository Memory
        └──→ task-specific retrieval
                    ↓
               Context Pack
```

Knowledge Concepts are Markdown with YAML frontmatter. They can record stable source IDs, signed Git+ citations, blob/gitlink dependencies, generated/verified metadata, lifecycle state, and temporal freshness. A changed dependency or expired `stale_after` marks knowledge for revalidation rather than automatically declaring it false.

Git+ imports and exports the Open Knowledge Format (OKF) as an interoperability surface while retaining Git-native signatures, evidence identity, and authority semantics.

```bash
# Browse the repository knowledge corpus
git+ knowledge list

# Verify current repository evidence for a concept
git+ knowledge check gotchas/worker-auth

# Exchange the corpus using OKF-compatible Markdown/YAML
git+ knowledge export --format=okf .gitplus/knowledge
git+ knowledge import --format=okf ./external-knowledge
```

Imported knowledge remains data. OKF `generated`/`verified` metadata never grants repository membership, capabilities, or instruction authority.

## Web Interface

The web interface in `src/ui/` provides a lightweight file browser, commit viewer, task manager, pull request inspector, session detail view, and agent Flight Recorder powered by Lit and Web Components.

The Flight Recorder joins Git-native Context Exposure with normalized OTel runtime signals, workspace transitions, tools, and resulting commits while preserving causal DAG structure. External observability traces can be linked when configured, but Git+ remains useful after external telemetry expires.

```bash
# Development mode: watch UI and bind embedded API server on :8000
GIT_ROOT=./repos npm run dev:ui

# Build production bundle and serve statically
npm run build:ui
git+ serve --root ./repos --ui
```
